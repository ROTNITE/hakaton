# Локальная аналитика сохранённых миссий

Запуск из корня проекта:

```powershell
python -B -X utf8 -m analytics.server --port 8140
```

Адрес: http://127.0.0.1:8140. Сервер слушает loopback, проверяет Host,
не вызывает среду и не меняет модельное время. Внешних фронтенд-зависимостей
и CDN нет. Roboto и соответствующая Apache 2.0 сохранены в web/fonts/.
Исходники: analytics/{server,store,metrics}.py, web/{index.html,styles.css,app.js}.

## Данные и целостность

Каталог читает missions, core-acceptance и quarter-v3/runs в
`D:/MetaRescue-output`. Визуальные проверки показывают собственные показатели
рендера. Сравнение и экспорт миссий используют нативные журналы Core.
Неполный архив и ошибка индекса показываются явно.

При первом открытии проверяются CRC, длины, индексы и SHA-256 нативных потоков,
хэш controller.jsonl.gz по манифесту. SQLite и сводки — производный кэш
в analytics/<run-id>. Перестроение зависит от манифестов, размера/mtime
исходных потоков и версий схемы/расчётов. На Windows соединения явно закрываются
перед атомарным переименованием. Один индексатор сообщает этап и число записей.

Журнал сохраняет все записи в трёх потоках, выдаёт страницы по 100 (максимум 250)
и ограничивает обычный ответ примерно 8 MiB. Поиск включает агент, цель, команду,
сообщение, решение, запрос, trace ID, тип и текст причины. Ссылки в карточке
открывают поиск по связанному ID. Переход к записи устанавливает время просмотра.
Исходный JSON остаётся доступен без преобразования.

Просмотр миссии использует до 251 выбранного секундного/публичного снимка,
сохраняя финальный. Истина среды и доставленные знания команды переключаются
явно. У инспектора есть время измерения, доставки и возраст позы. Геометрия,
опасности, реальные траектории и известные сетевые связи строятся из архивов.
Интерполяция не выдаётся за дополнительные физические измерения. Полная
телеметрия остаётся в журнале; детальный replay выбранного физического отрезка,
тепловые карты и общая шкала нескольких миров требуют следующего расширения.

## Показатели

Версия расчётов — metarescue.audit-metrics.v3. Расход энергии суммирует
накопленные consumed_wh, сохраняет остаток отдельно. Время решения контроллера
и wall_ms завершённых расчётов NSGA-II учитываются раздельно. Рендерные FPS
не выводятся из ускоренного моделирования. Если профиль кадра отсутствует,
это обозначается в интерфейсе.

M1 — сумма приоритетов фактически эвакуированных в финальном truth-срезе,
делённая на сумму приоритетов всех зарегистрированных к этому моменту целей,
включая не обнаруженные. При отсутствии исторических приоритетов M1 неизвестен.
Ещё не наступившие available_at исключаются при раннем cutoff. Тот же фильтр
используется для текущего кадра полного наблюдателя; исходная truth-запись
с шаблонами поздних появлений сохраняется без изменений.
M5 и итоговый официальный балл остаются неизвестными до внешних испытаний.
Остальные официальные показатели ещё не заявлены как вычисленные.

Фронты каждого раунда сохраняют seed, оценки, выбранные objectives и три
целевые функции. UI группирует одинаковые значения с числом кандидатов,
полный исходный фронт доступен в записи. HV и IGD+ математически реализованы
и проверены на контрольных примерах. Сравнение разных runtime-задач ими
не выполняется; нужны одинаковые заранее сохранённые постановки и нормировка.
Парный map-cluster bootstrap реализован, серия ещё не выполнена.

Сравнение показывает фактические эвакуации во времени. Парные разности
рассчитываются только при совпадении SHA-256 исходного мира. Это условие
не означает одинаковые полученные наблюдения и не доказывает преимущество
политики. Веб-интерфейс не смешивает результаты 2D и 3D.

## API и экспорт

Экран API читает проверенный экспорт accounting: текущий запуск и накопленный
снимок на дату архива, общий лимит, статусы, токены/пропуски, оценки стоимости,
физические подтверждения, сетевые попытки и полный JSON по раскрытию.
Неполный известный расход отделён от общего; фактический debit не подтверждён.
На standalone-13: run 0, cumulative 6/240, 7502 известных токена пяти ответов,
у шестой ошибки usage отсутствует. Денежные десятичные строки не округляются
до нуля. Просмотр и экспорт не обращаются к DeepSeek.

Доступны JSON сводки, CSV, TXT и ZIP со сводкой, всеми файлами запуска и
полным нативным архивом. ZIP создаётся во временном файле; память не растёт
на объём всего архива. Публичный API: /api/runs, /api/compare и
/api/runs/<id>/{summary,records,timeline,map,fronts,usage,export}.

## Теплокарты и просмотр подшагов

Индекс v3 сохраняет сжатые кадры просмотра и агрегаты при чтении проверенного
архива. Исходные записи доступны через прежний фильтр и экспорт. Кадры карты
содержат выбранные поля агентов, целей и динамических зон. Кэш нового индекса
хранится отдельно от прежнего. Перенесённый архив обнаруживается внутри
`core-runs/<episode_id>` от корня данных.

Теплокарта за весь эпизод использует сетку 10 × 10 м. Полный наблюдатель берёт
физические отсчёты 10 Гц. Для знаний команды учитываются уникальные времена
доставленной позы. Плотность показывает число отсчётов, слой слабой связи
показывает долю измерений без канала или с качеством ниже 0,5. API
`/api/runs/<id>/heatmap?basis=public|truth` возвращает обе величины.

В полном наблюдателе можно выбрать окно аномалии и отдельный подшаг Core,
прочитать фактическую позу и скорость и увидеть точку на карте. Публичный вид
использует только доставленные сведения. Проверка `analytics-browser-04`
сверила 701 наблюдение, 7000 отсчётов, десять окон, переключение источников,
два слоя теплокарты и проигрывание кадров. В окне остановки прочитаны точки
216,000 и 216,450 с. На ширине 390 px переполнения нет, ошибок JavaScript нет.
Четыре формата экспорта и ZIP с исходными потоками сверены в
`D:/MetaRescue-output/checks/analytics-http-03-build67/verification.json`.
