# Нативные журналы и точные повторы

## Читаемые записи связи контроллера

В новых запусках контроллер добавляет в `controller/controller.jsonl.gz` записи
`agent_communication`. Это производное представление уже доставленных публичных
наблюдений: события обнаружения цели или изменения опасности и сообщения,
дошедшие до inbox получателя. В записи есть отправитель, получатель, тип,
исходный `message_id`, ссылка на observation и доступные времена/данные.
Один и тот же event или сообщение inbox в рамках работы контроллера не повторяется.
События поверхности, которые не изменили публичное состояние, отдельно здесь
не отображаются; исходные нативные журналы сохраняются как прежде.

`delivered_report_view` относится к отчёту в `rescue-base`; `signal` — читаемое
имя события, а не буквальный новый пакет или запрос к Global AI.
`delivered_peer_message_view` содержит исходный payload сообщения, прочитанный
из доставленного inbox. Доставка в inbox становится видна контроллеру лишь с
очередным доставленным снимком получателя и может не попасть в него при потере
связи или ограничении истории. Время отправки, priority, confidence и ACK не
выдумываются: они присутствуют лишь там, где есть в исходных данных. Вид
активируется только для объявленных расширений Core; отсутствующий message ID
не считается доказательством доставки. Записи можно найти в аналитике по типу
`agent_communication` или ID, исходные observation/step_response остаются в
том же архиве. Старые архивы и замороженные сборки не преобразуются.

Формат `metarescue.indexed-json.v1`, реализация `MRCoreStore.*`/`MRCoreArchive.cpp`,
читатель `tools/native_archive.py`. Это хранение текущего Core-среза, не приёмка
всех событий, сценариев или аналитики. Прежние JSONL-архивы сохраняются отдельно.

## Данные и память

В `D:/MetaRescue-output/core-runs/<episode>/` три независимых потока:

- `public`: только доставленные наблюдения/решения/подтверждения и ошибки;
- `truth`: физическая телеметрия 10 Гц и внутренние события; HTTP её не публикует;
- `replay`: исходные тела step и точные исторические ответы, включая контролируемые
  ошибки. Тело сохраняется в base64, UTF-8 ответ — строкой. Ретрай сравнивается
  побайтно до проверки времени/текущего плана.

Каждый поток имеет `.records` и `.index`. У записи размером от 1024 байт
используется zlib, если результат меньше исходника. Индекс на диске — 24 байта
little endian: offset uint64, stored_size uint32, raw_size uint32, CRC32 uint32,
codec uint32 (0=raw,1=zlib). CRC относится к распакованным UTF-8 байтам. Публичные
записи имеют завершающий LF; JSON-парсер не использует замену ошибочного UTF-8.

Полные истории не хранятся в RAM. Для точного поиска остаётся индекс до 100000
фиксированных SHA1-digest → номер записи; SHA1 здесь только индекс, сохранённые ID
и тело дополнительно проверяются, коллизия останавливает обработку с ошибкой.
Лимит опубликован в capabilities. Реестр reset содержит до 4096 digest; только
последний reset сохраняет полное тело/ответ в памяти. Индексы очищаются на новый
эпизод, старые файлы сохраняются. Crash-resume эпизода не объявлен.

В памяти команды остаются до завершения/доставки подтверждения. StepResponse
содержит новые или изменившиеся результаты; отсутствие команды в последующем
ответе не отменяет её. После фиксации ответа завершённые состояния освобождаются,
незавершённые сохраняются. История и точные повторы доступны с диска.
Общий лимит очереди на агента учитывает и команды того же пакета; зависимая группа
при нехватке места отклоняется целиком, независимые могут приниматься частично.

## Публичное чтение и отказ записи

GET logs имеет собственный плотный публичный cursor. Private записи не создают
пропуски, количество/позиции скрытых объектов не попадают в курсор. Страница
ограничена 1000 записями и мягким бюджетом 8 MiB; одна более крупная запись может
быть возвращена целиком. Максимум одной записи 32 MiB, данных одного потока 1 TiB.
GET не меняет физику, RNG, доставку или сенсоры. Обновление файловых дескрипторов
при дописывании — только операция чтения: Windows/Unreal кэширует размер файла
при открытии и иначе не позволяет прочитать новый хвост.

Данные/индексы flush перед успешным ответом шага. Manifest сохраняет state,
статус/время эпизода, числа записей/байтов, live-команды и размер replay-индекса;
обновляется через `.part` и замену. `complete` означает завершённый архив, а статус
миссии хранится отдельно. Незакрытый процесс оставляет open/interrupted; ошибка
записи/flush/manifest переводит эпизод в failed с archive_io_failed, сообщение
остаётся в engine log. Тихого удаления записей или перехода на журнал в RAM нет.
Неисправный архив не подтверждает полное свидетельство даже при сохранённых кадрах.

Проверка после завершения потоково читает все записи, CRC/размеры/границы,
сверяет manifest, вычисляет SHA-256 файлов. Остаток без индекса и усечённый индекс
считаются неполным архивом. Runner связывает отдельный controller archive с
native archive; приватные потоки остаются в каталоге runner, вне HTTP контроллера.

```powershell
python -B -X utf8 unreal/launch.py --automation MetaRescue.Core
python -B -X utf8 tools/native_archive.py D:/MetaRescue-output/core-runs/EPISODE
# Опционально: потоковый экспорт в новый каталог, исходник сохраняется.
python -B -X utf8 tools/native_archive.py D:/MetaRescue-output/core-runs/EPISODE --export D:/MetaRescue-output/exports/UNIQUE
```

archive_io_failed. После ошибки хранения step отказывает до чтения replay:
