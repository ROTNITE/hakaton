## Публичное расширение

`capabilities.extensions` объявляет `metarescue.operator_directives.v1`.
Core Protocol остаётся1.0. Действие `issue_directive` доступно только сущности
kind=operator и проходит обычные доставку, задержку, потери и ACK команд.
Параметры объявлены JSON Schema в capabilities; неизвестные необязательные
поля не превращаются в инструкции и не сохраняются в требовании.

Новые требования содержат `action`, `reason` (1..128 UTF-16 единиц без
управляющих символов), `duration_s` (1..60 с). Действия:

| action | Параметры и смысл |
|---|---|
| hold | target_id известного мобильного агента; прежняя форма сохранена |
| set_priority | target_id публичной цели, priority1..3; действует на будущий выбор, действующий груз/рейс сохраняется |
| restrict_zone | bounds.min/max в метрах внутри карты, allowed_kinds; настоящая запретная область среды и публичная zone |
| message | text до512 UTF-16 единиц; неполное сообщение получает needs_clarification и само движения не вызывает |
| cancel | directive_id, expected_revision; отменяет своё требование |
| clarify | directive_id, expected_revision, instruction с полностью описанным новым требованием |
| confirm | directive_id, expected_revision; активирует pending_confirmation |
| request_confirmation | directive_id, expected_revision; запрашивает у контроллера актуальную интерпретацию/ограничение исполнения |

Для четырёх операций со ссылкой нужны action/reason/directive_id/expected_revision;
duration_s задаётся при новом требовании либо во вложенном instruction уточнения.
Чужое, истёкшее или устаревшее требование изменять нельзя. Повтор всей Core
Step-заявки дедуплицируется штатным механизмом. На доставке ревизия проверяется
повторно, поэтому две принятые конкурирующие правки не перезаписывают друг друга.
Не более64 ещё хранимых сервисных требований; отменённые удаляются по TTL.

`requires_confirmation=true` либо confidence<0,75 оставляет структурированное
требование в pending_confirmation. Состояние требования находится в
mission.directives и параметрах события; enum статуса самого события Core
остаётся new/active/resolved/expired. Приоритеты публикуются также в
mission.priorities (шкала1..3); контроллер проецирует их на свою шкалу0..1.
Это приоритет миссии: физические свойства пострадавшего в истине не подменяются.
При конфликте приоритетов выбирается последний updated_at, затем revision и id.
Отмена/истечение снимают именно соответствующую область/приоритет/hold.

Контроллер записывает operator_interpretation в фактическое Decision: исходное
требование/ревизию, интерпретацию, выбранные сценарии и ссылку на отправляемый
ответ. Ответ — send_message, успешность подтверждается completed+delivered,
а не фактом постановки в очередь. Доставленный inbox оператора входит в
communication.inbox его последующих доставленных снимков (последние32 сообщения).
Неполное/устаревшее сообщение не меняет маршрут. Hold при погрузке/разгрузке/
зарядке ждёт безопасной границы с явным объяснением; коалиционный автомат также
ждёт освобождения удерживаемого участника. Иные агенты продолжают работу.

## Ввод человеком во время автономного запуска

Продукт автоматически передаёт своему контроллеру файл operator-input.json
из каталога текущей подготовленной миссии рядом с control.json. Путь виден в
GET /v1/controller/health как operator_input_file. Для отдельного запуска:

```powershell
python -B -X utf8 tools/run_mission.py --layout "<world.private.json>" --operator-file "<operator-input.json>"
python -B -X utf8 tools/issue_operator.py "<operator-input.json>" --episode "<episode_id>" --expires-at 120 --instruction "<instruction.json>"
```

В Windows-поставке вместо python используется `python/python.exe` из поставки.
`instruction.json` содержит только параметры issue_directive, например:

```json
{"action":"hold","target_id":"<id из Observation>","duration_s":15,"reason":"inspect_unsafe_passage"}
```

CLI атомарно добавляет требование, не вызывает reset или step. expires-at —
последнее модельное время для постановки команды; duration_s отсчитывается от
её настоящей доставки. Файл привязан к одному episode_id, максимум64 заявки
в файле/64KiB и256 уникальных локальных ID на эпизод. Один ID нельзя переиспользовать
с другим содержимым; для уточнения создаётся новая заявка со ссылкой на native
directive_id и текущую revision. Получить их можно из mission.directives либо
service_result исходной команды. После reset используется новый файл эпизода.

Невалидный JSON/схема, неизвестный публичный ID, чужая/устаревшая ссылка и
управляющие символы отклоняются локально с записью operator_input; это не
прерывает миссию. Одна ошибочная прежняя заявка не блокирует следующую корректную.
Пауза шага мира не расходует время требования; новые команды не добавляются
поверх safe_stop. Локальное queued_locally не означает доставку или исполнение.
