# RescueQuarter v3: матрица приёмки

Срез 2026-11-10 перед первой согласованной сборкой команды. Это перечень
обязательств исходного плана, а не сокращённый план по уже работающей части.
Сборки/нативные прогоны выполняет основной агент последовательно. У визуального
агента — геометрия/камеры/подготовка, у агента безопасности — исполнение техники,
у аудитора — проверки/свидетельства. Общие C++ заголовки замораживаются на сборку.

Статусы: **проверено** — есть прямое свидетельство указанного объёма;
**частично** — подтверждена только часть; **провалено** — имеется противоречащее
свидетельство; **ожидает** — необходимый результат ещё не получен. Старые прогоны
не принимаются за проверку текущей командной ревизии. `verification.passed`
означает только перечисленные программные проверки, а не приёмку визуала.

## Следующая последовательность испытаний

1. Заморозить исходники, выполнить одну полную сборку, генерацию ассетов,
   материалов и карты, затем readback. Проверить окна, интерьер и провал
   крупным планом; исправить визуальные ошибки до длительных серий.
2. Первым запустить crossing на 100 с, поскольку уже известен реальный контакт.
   Затем остальные шесть traffic fixtures. Проверять и достижение финиша,
   и историю контактов, и сохранение груза/команд.
3. Восемь изолированных эффектов, все нулевые вероятности, отдельный физический
   пробник поверхностей. Смотреть кадры настоящего места события по ID.
   Коэффициент стоимости не считается доказательством физического замедления.
4. Static 270 с с доставкой, три random по 480 с, повтор одного или всех seed
   той же ревизии, legacy 90 с. Свежие файлы архивировать до следующего запуска.
5. Снять showcase для видео, проверить визуал каждого сценария, составить
   итоговый отчёт со свидетельствами и ограничениями, проверить хэши/diff.
   Goal закрывается после выполнения всех требований.
