# MetaRescue v0.3 — приём исходников и проверка

2026-11-09. Пользователь передал готовый архив после фиксации спецификации. Это текущая исходная база динамического 2D-бенчмарка; наличие замечаний ниже не скрывается под формулировкой «полностью принято».

## Происхождение

- Оригинал: `docs/sources/MetaRescue_Benchmark_v0_3.zip`.
- SHA-256: `5b36cc61df3fda83e489fab70aa82a6d0eb695d04cc0c70a7be01c7edc2a3cdc`.
- **16 файлов импортированы без изменения** в `benchmarks/metarescue-v0.3/`.
- Пофайловые хэши: `docs/sources/metarescue-v0.3-manifest.json`.
- Прочитаны все 16 файлов: ядро, сервер, запуск, тесты, README и HTML/CSS/JS. v0.2 остаётся отдельным неизменённым историческим ориентиром.

README автора v0.3 прямо указывает, что версия реконструирована по функциональному описанию: ZIP v0.2 не был доступен при её создании. По структуре кода это действительно самостоятельная переработка, а не буквальный патч v0.2. Не смешивать между версиями результаты даже одинакового seed.

## Что подтверждено кодом

`world.py` создаёт карту, полную заранее определённую популяцию с `appeared_at`, общую ленту событий и отдельный изменяемый `TerrainState` для каждой симуляции. `optimizer.py` содержит базовые эвристики и недоминируемый эволюционный отбор. `simulation.py` исполняет движение, сканирование, погрузку/доставку, события и перепланирование. `server.py` отдаёт три страницы и `/api/simulation`; `benchmark_batch.py` использует то же ядро для CSV.

Сохраняются **5 разведывательных политик, 4 эвакуационные и 5 полных связок** с прежними ID. В v0.3 оптимизируется короткое назначение — одна следующая задача свободному агенту, а не весь маршрут миссии. Вариация NSGA-II в этой версии использует мутацию и турнир с ранжированием/crowding/элитизмом; crossover, кэш фитнеса и перенос популяции из v0.2 не сохранены. Это нужно учитывать в исследовательских выводах и сравнении реализаций.

Все восемь регуляторов есть. **Фактическое окно — 30 модельных секунд**: один шанс появления каждого типа на весь участок. Это заменяет предложенные ранее 10 с в нашей предварительной спецификации; единица явно указана в UI/README/API. Огонь/вода могут распространяться ещё в двух последующих окнах с условной вероятностью; вероятность слайдера задаёт начало, а не скорость распространения.

Последствия:

- новые коды 4/5/6/7/8 — грязь, повреждённая дорога, огонь, паводок, обрушение;
- грязь и дорога меняют стоимость A*; огонь, паводок и обрушение закрывают клетки;
- при изменении стоимости/проходимости сбрасывается кэш пути и связных компонент;
- дым действует 90 с с множителем видимости 0.52, плохая видимость — 100 с с множителем 0.62; эффекты перемножаются; пожар может создавать дым на 70 с;
- сенсорный результат зависит от seed, человека, 15-секундного окна и сектора; повторное сканирование может дать иной результат;
- новая цель заранее существует в истинном сценарии, но до `appeared_at` не доступна обнаружению; online приходит только сектор сигнала, затем нужен дрон. В offline-эвакуации координаты новой цели передаются сразу — это явно отдельный режим;
- отказ эвакуатора отменяет рейс; перевозимый человек остаётся около текущей позиции вместо возврата к исходной точке. Положение округляется до клетки, что остаётся упрощением;
- спасение регистрируется только после возвращения и высадки.

Оповещения об изменившейся местности в v0.3 считаются мгновенно общедоступными. Это **объявленное допущение бенчмарка**, а не реализованная ограниченная связь или отдельная карта знаний. Для нормативной среды нельзя передавать контроллеру будущий календарь/истину из лабораторного `public_map`.

## Что отличается или потеряно относительно v0.2

| Область | Факт v0.3 |
|---|---|
| OR-Tools | Опциональной панели/адаптера нет; v0.2 сохраняется для этого эксперимента |
| Экспорт JSON кнопкой | В UI кнопка отсутствует. JSON доступен через API, CSV — через CLI |
| venv | Автоматически не создаётся, используется установленный Python; папка-заглушка сохранена |
| Скорость воспроизведения | Подписи 1×/30× соответствуют внутренним 6/180 модельным с/с; нужен пересмотр обозначений |
| Статическая модель | Другие генерация, скорость, энергия, сенсор, rough=1.55 вместо 1.45; нулевая динамика не даёт тех же результатов, что v0.2 |
| Вероятности по умолчанию | HTML range имеет step=5, а часть default value равны 12/14; браузер округляет их. CLI по умолчанию использует исходные 12/14. Для точного повтора передавать фактические параметры |
| Отчётность | CSV включает основные настройки и метрики, но не все восемь вероятностей/ленту. Для воспроизведения сохранять команду/config или JSON API рядом |
| Метрики | Количество людей в промежуточном рейтинге растёт с событиями. В конце знаменатель общий; рейтинги разных моментов нельзя трактовать как оценку при неизменном N |

Следовательно, требование «всё v0.2 плюс динамика» выполнено **не буквально полностью**. Эти различия не исправлялись тайно в присланном коде.

Включают настоящий loopback HTTP, настройки вероятностей, 5 связок, одинаковую ленту, отсутствие раннего обнаружения, динамические маршруты, поздний сигнал после полного охвата, отказ с грузом и максимальный парк. В тесте HTTP 400 есть ResourceWarning о незакрытом объекте HTTPError; это предупреждение тестовой обвязки, не провал проверки.

Дополнительно выполнена серия трёх seed 2026–2028: urban, 25×25, 16 первоначальных людей, 3 дрона, 4 эвакуатора, штатные CLI-вероятности v0.3. Сырые 15 строк — `artifacts/metarescue-v03/results-3-seeds.csv`; это smoke-серия, не исследование 30×3. Метрики CPU относятся к текущему ПК/нагрузке.

Среднее число доставленных: Greedy+Greedy 14.00; Frontier+Local Search 14.67; Scout NSGA-II+Greedy 13.33; Greedy+Rescue NSGA-II 14.33; NSGA-II+NSGA-II 13.33. Это не даёт основания объявлять NSGA-II победителем и не является универсальным сравнением на всех постановках. Конфигурация и исходный SHA сохранены рядом в `series-config.json`.

План браузерной проверки: 5 полей общей миссии; три страницы; восемь вероятностей и новая конфигурация; шаг/пауза/перемотка; календарь и журнал; раздельные графики и окончание работы в таблице; desktop/mobile без переполнения документа. ## Два воспроизведённых граничных дефекта

Команда:

```powershell
python -B -X utf8 tools/audit_metarescue_v03.py
```

Выходит с кодом **1**, намеренно сигнализируя о найденных проблемах. Отчёт — `artifacts/metarescue-v03/boundary-audit.json`. Это прямые граничные вызовы сервисных методов, **не утверждение, что обычная серия целиком не работает**:

1. **Проверка энергии сервисного действия.** При 0.1 Wh у робота у базы и перевозимом человеке `on_robot_done(..., 'to_base')` назначает высадку стоимостью 2.5 Wh. После `advance` остаток равен 0, накопленный расход 2.5, человек засчитан спасённым. Нужен общий охранный механизм для движения и сервиса: проверять доступную энергию, обрезать/отклонять недопустимое действие, не скрывать перерасход через `max(0, ...)`.
2. **Непрерывность перепланирования.** Из фактической позиции `[1.4,1.0]` новый путь начинается в `[1,1]`, потому что A* округляет старт, а исполнитель затем берёт первую точку этого пути. Необходимо добавить физически допустимый соединительный участок от реальной позиции и учитывать его время/энергию. Особенно важно для следующего переноса в 3D.

Кроме того, локальное движение распределяет время по геометрической длине пути при общей взвешенной длительности; оно ещё не замедляется только на конкретном грязном ребре. Защищённое отделение истинной/известной карты, одинаковый CPU-бюджет, HV/IGD+, нормативные метаоперации и 3D не реализованы этим архивом.

Решение: принять v0.3 **как сохранённую текущую базу для дальнейшей разработки и экспериментов**, с открытым списком ограничений. Для следующей рабочей редакции сначала закрыть энергетическую охрану и непрерывность, затем вернуть нужный паритет функций v0.2. Оригинальные архивы и их хэши сохранить.
