# Часы исполнения Core и дробные границы

`FMRCoreClock` продвигается только после действительного физического кадра.
Внешний step имеет длину 1 с либо заканчивается раньше по исходу/горизонту.
Максимальный шаг исполнения 1/60 с; внутри него выделяются короткие части на
известные моменты доставки, ACK, сенсора, телеметрии, событий и окончания step.
Это изменение физического исполнения, а не округление timestamp ответа.

Ранее время вычислялось как ticks/60: при radio latency .123 первый ACK получался
на .2666667 вместо .246. `core-clock-01-repro` действительно воспроизвёл это
расхождение и сохранён как failed. Такой способ нельзя использовать для новой
ленты с моментами, не кратными 1/60.

Новый clock хранит прошедшее модельное время, границу внешнего шага и число
исполненных частей. В accelerated режиме следующая часть задаётся через FApp
fixed delta; в realtime — также через следующий engine fixed frame rate.
Оба режима используют одинаковые границы. После шага idle-rate возвращается к
60, поэтому короткий конец шага не превращает паузу в цикл с тысячами кадров.
По установленному UE5.8.4 engine loop HTTP/core ticker исполняется после
GEngine.Tick: установленный интервал относится к следующей физике.

Полученный движком Dt сверяется с заданным интервалом; существенное расхождение
останавливает эпизод с execution_clock_mismatch. Позы/дистанция/Wh считываются
после физики. Sensor 2 Гц и telemetry 10 Гц используют модельные интервалы,
а не число кадров. Срок доставки истекает на самой границе deadline, до попытки
доставки. GET не вызывает ни clock.Advance, ни доставку, ни сенсор.

Приватные truth_snapshot фиксируют начальное состояние, каждый внешний шаг,
терминальное состояние (включая дробный конец) и close: фактические агенты,
люди и динамические PhysicsPieces. Это снимок этих подсистем; будущие категории,
сетевые RNG/буферы и все сценарные состояния ещё должны быть добавлены при их
реализации. Публичный HTTP этих снимков не возвращает.

Локальный AcceptedCommands digest освобождается после завершённого подтверждения
и фиксации результата. Авторитетный точный повтор остаётся в центральном disk
replay до reset. Manifest дополнительно показывает число оставшихся agent digest.
