# Продуктовое управление из Unreal

Участок утверждённого этапа 7, начат 2026-11-12 после сборки52 и проверки
тоннеля. Это план реализации, до нативной приёмки возможности ниже не считать
подтверждёнными. Нормативный Core1.0 и отдельный Python-контроллер сохраняются.

## Порядок

1. Добавить проверяемый управляющий канал runner→controller: running/paused/
   stopping и монотонное число одиночных шагов. Проверка на границе внешнего
   шага; GET не продвигает модель. Stop отправляет нормативный safe_stop и
   ждёт фактического торможения. Исходные CLI без канала работают как раньше.
2. Подготовка конфигурации отдельным helper: Settings.parse, генерация,
   preflight, уникальные private/public файлы, пресеты, статусы и ошибки.
   Никаких приватных данных в контроллер. Присоединяемый runner проверяет PID
   единственного Unreal и сохраняет обычные журналы/архивы/freeze.
3. Нативная GameInstance хранит настройку и собственный helper между сменами
   карты. Подготовка не запускает второй Unreal. Новая карта читает готовый
   layout, запускает Core, затем runner подключает контроллер через HTTP.
4. Slate-настройки и оперативные кнопки, инспектор доставленных сведений,
   предложенный/принятый/подтверждённый план, независимые слои/следы. Полный
   наблюдатель явно отделён от представления команды. Часы HUD — эпизодные.
5. Unit, Automation и нативный сквозной UI-прогон: настройка→пауза→шаг→
   движение/погрузка→остановка→повтор. Реальные кадры и сохранность входов.

## Границы и решения

- Пауза применяется после текущего внешнего шага (не более1 модельной секунды);
  интерфейс показывает ожидание подтверждения. Она сохраняет позу, груз и план.
- В безопасной остановке сначала выполняется Core safe_stop, затем close;
  закрытый эпизод остаётся на экране до следующего запуска.
- Контроллер не читает private layout, GameInstance или истину. Инспектор
  команды использует тот же cached Observation с возрастом/доставкой сведений.
- Секрет хранится вне проекта, UI получает только наличие и режим/ответ API.
- Для нативных форм необходимы модули Slate/SlateCore; это поставляемая часть
  Unreal, новых сторонних библиотек нет. API сверяется с исходниками UE5.8 и
  [документацией Epic](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/Slate/SNumericEntryBox).
- CLI/приёмочные стенды и старый физический demo не переименовываются в продукт.
- Контрольные образцы требуют OFF и собственной фиксированной координации.

## 13 ноября: занятый порт здоровья

В оконной проверке candidate09 выбранный порт 8181 принадлежал существующему
wslrelay. На Windows обычный SO_REUSEADDR позволял второму HTTP-слушателю
разделить его с прежней службой. Приложение оставалось на connecting; попытка
не принята и сохранена в checks/p0-window-20261113-02 на D.

HealthServer теперь использует эксклюзивное владение Windows-сокетом и запрещает
повторное использование адреса/порта. run_product проверяет доступность портов
среды и здоровья до создания session, аналитики и Unreal. Проверка не закрывает
чужой слушатель; остаётся небольшое окно между проверкой и последующим bind,
которое закрывается обязательным эксклюзивным bind HealthServer.

Регрессия воспроизвела двойной bind при SO_REUSEADDR, затем прошла. Проверены
отказ до запуска native и неизменность чужого владельца. Фактический запуск на
занятом 8181 завершился явным RuntimeError; root 216/216. Candidate10 получает
только controller/health.py и tools/run_product.py поверх проверенного native 09;
его отдельная распаковка и оконная проверка завершились успешно.
