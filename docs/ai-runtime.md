# Global / Local AI: исполняемый срез

Реализация: `controller/ai.py`, `ai_contracts.py`, `advisor.py`, `ai_policy.py`.
Источник идеи — неизменённый v0.5.2 `ai_control.py` и `strategy_engine.py`.
Это не отметка полной конкурсной приёмки: актуальные результаты находятся в
`quarter-v052-execution.md` и `quarter-v052-acceptance.json`.

## Провайдер и бюджет

`deepseek-flash`, официальный HTTPS `/chat/completions`, JSON Output,
`thinking: {type: disabled}`. Настройки сверены 2026-11-11 с первичными источниками:
[Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode/),
[JSON Output](https://api-docs.deepseek.com/guides/json_mode/),
[Models](https://api-docs.deepseek.com/quick_start/pricing/).
OpenAI SDK не добавлен: используется стандартный `http.client` с проверкой TLS.
Редиректы и неофициальный endpoint не поддерживаются.

Ключ читается из `DEEPSEEK_API_KEY` либо внешнего `--ai-key-file` (имя `API` также
поддерживается). В запросе модели, журнале и manifest ключа нет. Заголовки HTTP
не записываются; ошибочные тела ответов редактируются при совпадении с ключом.
Заданный ключ и успешный API-ответ — разные состояния; в MOCK/OFF/REPLAY API не
подтверждается. Успешный HTTP/JSON также не означает применение предложения.

`LiveBudget` использует kernel lock, атомарную замену JSON и fsync. Резервация
учитывается **перед сетью**, включая ошибки, тайм-ауты и смерть процесса.
Незавершённая резервация не возвращает квоту. Повреждённый/недоступный ledger
блокирует новые запросы. Общий лимит не может превышать 240; production ledger —
`D:/MetaRescue-output/ai-budget.json`. Не удалять и не обнулять при новом эпизоде.
Автоматических сетевых повторов провайдера нет.

## Выбор и исполнение

На13.11 подтверждено физическое влияние Global на будущую очередь:
S1-05-O1-dual-global, выбор144, три действующие команды сохранены, новый
person-4 pickup379,8/handover477,9667. Загруженный mobile-1 продолжил прежний
рейс на192,51м. Общий исход5/12/time_limit,0 контактов; доказательство применения,
а не сравнительного превосходства. Отчёт
`D:/MetaRescue-output/checks/global-queue-series-audit-20261113-01/native-s1-05-o1.json`.

Global получает белый список доставленных знаний, пять настоящих вариантов NSGA-II
и три продолжения каждого. Возвращает KEEP или SELECT с ID кандидата. Проверяются
эпизод, request ID, версия, срок, известность целей, состояние носителей, энергия,
прогнозируемые спасения и фактическое отличие очередей. Занятый носитель сохраняет
текущий рейс; меняется будущая очередь и профиль следующего поиска. Полные фронты
пишутся отдельно, а не раздувают prompt. Расширенные коалиции и операции Core
будут добавлены в соответствующем конкурсном этапе.

Local имеет отдельную память до 8 записей на мобильного агента. Он получает свою
доставленную телеметрию и предложенные программой действия; свежие отчёты остальных
агентов ему не выдаются автоматически. Первое назначение и физическая блокировка
маршрута — текущие триггеры. Решения: KEEP, DETOUR, HOLD, ESCALATE.
При блокировке исполнитель сначала тормозит, затем ждёт AI. Геометрия препятствия
приходит от реального safety sweep, для HISM — конкретного экземпляра.
После ответа маршрут повторно строится из фактической позы, проверяется энергия
с возвратным резервом и горизонт; задача/груз не очищаются. При недоступном маршруте
робот удерживается с явным объяснением, остальные продолжают выполнять команды.

Асинхронный mailbox ограничен одним Global и четырьмя Local одновременно.
Тайм-аут даёт резервное управление, но работающий HTTP worker занимает свой слот
до возврата: reset не может создать неограниченное число осиротевших запросов.
Устаревший ответ сохраняется в журнале и отклоняется. Полные журналы не обрезаются
из-за ограниченного размера оперативной памяти агентов.

Версии Local раздельны для каждого агента; обновление Global не делает ответ
другого агента автоматически старым. Первые обращения сохраняются в FIFO при
заполненном mailbox. Перед отложенным применением повторно проверяется TTL.
Профиль Global сбрасывается при новом эпизоде и заново проходит gate на следующей
задаче оптимизации: прежняя допустимость не разрешает новую прогнозируемую потерю
спасаемых. Worker получает снимок профиля; результат, вытесненный новым профилем
или запросом пересчёта, не применяется. request_replan сохраняет реальные текущие
действия/груз и объединяет повторные триггеры, оставляя по одному worker на задачу.

Постоянные usage/cache/cost/unknown и общий бюджет описаны в [api-accounting.md](api-accounting.md).
Нативные потоковые записи/точный retry — [native-journals.md](native-journals.md).

## Время, режимы и повтор

`python -m environment.main --layout ... --realtime --exit-on-close` включает
wall-paced выполнение 60 Гц; ускоренный режим оставлен для OFF/MOCK/REPLAY.
`controller.main --ai-mode LIVE` проверяет capability времени до первого AI-запроса.
Это режим времени исполнения, а не измерение FPS. При медленном рендере модель
может отставать от wall; реальное отношение отдельно измеряется в native-проверке.

`--ai-mode MOCK` детерминированно выбирает допустимый вариант; не вызывает API.
`--ai-mode REPLAY --ai-replay <controller.jsonl.gz или planning.jsonl>` требует
совпадения семантического входа. Новые episode/request/command UUID не являются
знаниями. Ответ доступен на записанной модельной задержке без sleep контроллера;
пропуск записи приводит к явному резерву. Это не допуск произвольно похожих входов
и не обещание побитового повторения физики.

## Границы текущей проверки

Unit-тесты не подтверждают LIVE-соединение или физический результат. Нативный
fixture восстановления намеренно подменяет один загруженный маршрут неверным
срезом через объявленный реальный ствол; подмена записывается отдельно и не
используется в зачётных/сравнительных сериях. Его горизонт 1000 с не смешивается
со статическим fixture 480 с и будущими 450 прогонами.
