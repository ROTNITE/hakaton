# Независимый аудит P0, 13 ноября 2026

Все требования ТЗ пока нельзя объявлять выполненными. Этот срез завершает
подготовку отдельного исходного supplement и проверяемых примеров для D03/D06,
а также даёт дополнительные свидетельства D07/I08. Полные D03–D07 не переводятся
в verified автоматически: нет финальной приёмки единого комплекта с ассетами,
Windows, запиской и видео. Выявлен отдельный пробел §5.3.

Работа выполнена без субагентов. Второй Unreal, сборка, cook, импорт и LIVE API
не запускались. Runtime-код, сцены, AI ledger и общие execution/acceptance не менялись.
Новые файлы проекта: tools/package_source_review.py, tests/test_source_review_package.py
и этот отчёт. Дополнительная приёмка хранится отдельно, чтобы не перезаписать работу
основного чата. При включении в общий выпуск перенести только подтверждённые
подэтапы и сохранить перечисленные ограничения.

## Что завершено

- Создан кодовый ZIP source03: 510 входных файлов, 512 файлов с инструкцией и
  версиями зависимостей; каждый проверен по SHA-256, весь ZIP по CRC. Входы за
  время копирования не изменились. Файлы не заменяют binary-ассеты и полный выпуск.
- Из распаковки с кириллицей/пробелами: 226/226 основных тестов; v0.5.2 55/55,
  v0.3 30/30, Unreal tools 10/10 прошли в source02. Все 111 файлов соответствующих
  компонентов source02/source03 идентичны по SHA. Тесты исходного импортированного
  бенчмарка не менялись. В 226 входят 10 тестов нового упаковщика.
- Кодовый supplement связан с candidate10: совпали 53 общих Python-файла и
  77 C++/Config/descriptor-входов по манифесту сборки. Это проверка привязки
  исходников, а не новый запуск или пересборка Windows.
- В копии применено штатное преобразование упаковщика Windows: AndroidFileServer
  отключён, его editor-настройки исключены. Оригинал не изменён. Включён только
  проверенный пустой upstream secret.env (`API=`); непустой шаблон отклоняется.
- Проверка по одному известному настроенному ключу не нашла совпадений; в .ini
  supplement нет поля SecurityToken. Это не доказательство отсутствия неизвестных
  секретов и не заменяет проверку финального общего архива.
- Заново проверены CRC, размеры, индексы и хэши 4 сохранённых нативных архивов;
  исходные файлы не изменились. Экспортированы реальные записи семи операций
  независимого клиента и реальные записи контроллеров трёх сравнительных миссий.
  У каждой записи сохранены исходные ID, путь и нулевой индекс. Это исторические
  эпизоды: их результаты не выдаются за свежие прогоны текущего source03.
- У всех 160 требований снимка матрицы доступны указанные свидетельства:
  67 verified / 55 partial / 38 pending, пропавших ссылок 0. Эти числа включают
  P1/v3, не являются процентом выполнения ТЗ. Наличие отчёта не доказывает
  поведение на новой ревизии.

## Обязательный пробел: оператор по §5.3

Постановка, стр. 5, требует не только директиву удержания: нужны изменение
приоритетов, ограничения, неполные сообщения, запрос подтверждения, отмена и
уточнение прежних требований. MRCoreServices.cpp принимает issue_directive
только с action=hold, MRCoreContest.cpp и environment/disturbances.py также
ограничивают операторскую директиву hold. FixedWorkflow.hold_orders обрабатывает
только удержание. События смены приоритета и запретной зоны сами по себе не
доказывают управление ими оператором с подтверждением/отменой.

Воспроизведение на source02: hold принят; cancel, clarify, request_confirmation,
set_priority и add_constraint возвращают INVALID_REQUEST / unsupported directive.
Имена этих пробных действий не навязываются протоколу: вывод о пробеле основан
также на просмотре native-команды и обработчика контроллера. Успешная проверка
C12 доказывает исполнение hold и автономный эпизод, но не весь §5.3.

Следующий шаг P0: на безопасной границе основного чата определить публичную
модель директив, добавить отмену/уточнение/подтверждение и связь приоритетов и
ограничений с оператором, вести конфликт с безопасностью и доставленные ACK.
Проверить это unit-тестами и настоящим нативным эпизодом. Здесь runtime не
изменялся, чтобы не нарушить выполняющуюся Windows-приёмку.

разрешения противоречия. Сохраняются вопрос организаторам и граница, описанные
в stage-1-interaction.md §16 и core-orbital.md. Core enum самовольно не менять.
