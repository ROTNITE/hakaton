# MetaEvolution Rescue / Rescue Lab

Автономный 2D-бенчмарк параллельной разведки и эвакуации. Четыре поля показывают исполнение алгоритмов на одинаковой карте, отдельные графики и таблица позволяют сравнивать результат. Работает локально, без облака и внешних пакетов.

## Запуск на Windows

1. Установите **Python 3.10 или новее** с официального [python.org](https://www.python.org/downloads/windows/). В установщике включите Python Launcher или Add Python to PATH.
2. **Распакуйте весь ZIP** в обычную папку. Пробелы и кириллица в пути допустимы.
3. Дважды нажмите **main.cmd**. Он запускает `main.py`; при первом запуске создаётся `venv`, затем открывается браузер.
4. Оставьте окно сервера открытым. Закрытие окна или Ctrl+C останавливает приложение.

Интернет, pip, Node.js, Unreal и Visual Studio для этого бенчмарка не требуются. Файл `requirements.txt` намеренно содержит только комментарии: всё выполнено на стандартной библиотеке Python. Готовое venv не переносимо между компьютерами, поэтому в архиве есть папка-заготовка, а само окружение создаётся на вашем ПК.

Из терминала в папке архива:

```powershell
python -B -X utf8 main.py
# Без автоматического браузера и без создания venv:
python -B -X utf8 main.py --no-venv --no-browser --port 8765
```

Адрес будет напечатан в консоли, обычно `http://127.0.0.1:8765`. Если порт занят, выбирается свободный; используйте напечатанный адрес. Страницу `index.html` отдельно открывать не нужно: ей требуется локальный Python-сервер. macOS/Linux: `python3 main.py`.

## Что нажимать

- **Разведка** сравнивает полосовой обход, ближайший неисследованный сектор, прирост покрытия и NSGA-II. Координаты людей заранее неизвестны планировщикам.
- **Эвакуация** сравнивает ближайшего человека, дедлайны, локальный поиск и NSGA-II. Разведка идёт параллельно; её метод выбирается слева. **Все четыре эвакуационных алгоритма получают один и тот же поток обнаружений.** Это изолирует качество распределения задач от качества разведки.
- `+1 секунда` делает один шаг. `Запустить` / `Пауза` управляют воспроизведением. Темп `Макс.` ускоряет выполнение, не меняя модель. `↺` повторяет тот же seed. Настройки применяются отдельной кнопкой со сбросом.
- Можно менять обе стороны карты (20–120), людей (1–120), дронов (1–12), роботов (1–16), завалы, радиус обзора, батареи, горизонт, популяцию и поколения NSGA-II.
- **Скрытые люди** — только режим наблюдателя. Он не раскрывает координаты алгоритмам. **Маршруты** показывает исполняемые пути.
- Под каждой картой — свой график с одинаковыми шкалами времени и количества людей. Четыре кривые друг на друга не накладываются.
- **Поколения NSGA-II** показывает реально записанные поколения поиска и проекцию фронта Парето. Сохраняется последний эволюционный раунд с выполнимым планом; время этого раунда указано. Просмотр ползунка не запускает новую оптимизацию.
- **Серия** использует уже применённые настройки и последовательные seed: исходный, исходный+1 и т.д. Прогресс и отмена работают независимо от анимации. CSV/JSON доступны для отдельного опыта и всей серии.

## Модель и алгоритм

Местность известна из условного спутникового снимка: непроходимые здания и проходимые, но более медленные завалы. Все пострадавшие размещаются в связной с пунктом области; их положение скрыто от планировщиков до обнаружения. Обзор идеальный в радиусе, без окклюзии зданий. Дроны летают над препятствиями со скоростью 3 клетки/с. Клетка и единица энергии условные; координата `z=0` оставлена в снимках состояния, но это ещё не 3D-симулятор.

Наземный путь — взвешенный кратчайший путь Дейкстры в четырёх направлениях. Скорость робота 1.25 клетки/с без груза, 1.05 с грузом; стоимость ребра учитывает завалы. Энергия на ребро равна его стоимости без груза и 1.35 стоимости с грузом. Извлечение занимает 2–6 с, передача в пункте 2 с, сервис расходует 0.08 энергии/с. Один робот перевозит одного человека за рейс и возвращается в пункт. Зарядка доступна только там: 10 энергии/с у роботов, 12 у дронов; расход считается накопленным, зарядка его не обнуляет. Потребление зарядной станции не моделируется.

У людей есть воспроизводимые условные дедлайны. Спасение засчитывается **после передачи в пункте до дедлайна**, а не при обнаружении или подъезде. Истёкший дедлайн не даёт баллов; начатый рейс возвращается в пункт. Это учебная постановка, не медицинская модель.

**NSGA-II реализован в проекте:** недоминируемая сортировка, crowding distance, бинарный турнир, OX-кроссовер перестановок, swap/reversal-мутации, элитарный отбор родителей и потомков. Результат — один план из найденного фронта Парето по явно заданному предпочтению. Это приближённый поиск; глобальная оптимальность не обещается. [Описание механики NSGA-II](https://pymoo.org/algorithms/moo/nsga2.html), [перестановочные операторы](https://pymoo.org/customization/permutation.html).

Разведка оптимизирует новый охват, время покрытия плана и энергию полёта. Хромосома — порядок общеизвестных секторов; декодер распределяет посещения между свободными дронами с запасом на возвращение. Скрытых людей в функции качества нет. Для быстроты NSGA рассматривает до 32 перспективных/равномерно выбранных секторов, глубина плана — до двух точек на свободный дрон. Остальные методы обходят ту же публичную сетку; полосовой обход сохраняет её порядок.

Эвакуация оптимизирует число своевременных доставок, среднюю прогнозную задержку (необслуженные задачи получают штраф горизонтом) и расход энергии. Хромосома — порядок уже обнаруженных людей. Общий декодер назначает задачи роботам с учётом занятости, зарядки, вместимости и дедлайна. В одном вызове рассматриваются до 60 ближайших по дедлайну известных задач **у всех методов**; остальные остаются для последующих перепланирований. Перепланирование возможно каждые 5 модельных секунд, свободным роботам выдаются первые задачи плана; исполняемый рейс не прерывается. Прогноз декодера не включает дискретную задержку следующего перепланирования, поэтому прогноз и фактический итог могут отличаться.

Ускорения: кэш путей и масок обзора, битовые маски охвата, кэш оценки перестановок, небольшие горизонты планирования, стартовые жадные решения, перенос предыдущего порядка. Локальный поиск начинает с тех же эвристических порядков и использует swap/insertion с тем же лимитом попыток `population × (generations+1)`; это сопоставимый лимит оценок, **не одинаковое CPU-время**. Время сортировки NSGA учитывается в CPU.

## Баллы и показатели

Для одной страницы:

```text
S = 100 × (K + 0.49 × T + 0.24 × E) / (N + 0.73)
T = среднее (1 − время результата / горизонт)
E = max(0, 1 − накопленная энергия / (3 × сумма ёмкостей команды))
```

K — найдено (разведка) или своевременно доставлено (эвакуация), N — всего людей. При K=0 балл равен 0. В разведке ёмкость команды — батареи дронов, в эвакуации — роботов и общих дронов. Скорость и энергия дают вместе не более 0.73: **один дополнительный человек всегда важнее обоих бонусов**. Это открытое предпочтение проекта, а не универсальный научный рейтинг. Не сравнивайте баллы разных режимов/настроек напрямую.

Таблица показывает:

- **Завершение** — остановка работы алгоритма, включая частичный результат/лимит; в разведке успешное завершение включает возвращение дронов.
- **Все** — момент последнего обнаружения/доставки, только если обработаны все люди; иначе `—`. Отличается от времени завершения.
- Среднее обнаружение от старта (разведка) или от обнаружения до передачи (эвакуация), секунд на одного = прошедшее время / результат, производительность людей/мин.
- Накопленную энергию, землю/воздух, энергию на человека. Нулевой результат даёт прочерк для средних на человека.
- CPU среднего/максимального вызова и число уникальных оценок. В эвакуации здесь CPU **своего** планировщика; стоимость общей разведки дополнительно записана в JSON опыта.

Модельное время детерминировано seed и настройками; ускорение анимации его не меняет. **CPU — реальное время на вашем компьютере, оно не добавляется к дедлайнам.** Это позволяет отделять качество плана от затрат алгоритма; для реального робототехнического применения потребуется стенд с учётом задержек вычисления и управления.

В серии выводятся среднее и выборочное стандартное отклонение, доля побед (ничья делится), парная разница баллов NSGA-II с соперниками и 95% percentile bootstrap по seed (2000 повторов, минимум 3 карты). Это описательная оценка с маленькой выборкой, без поправки на множественные сравнения. Для уверенных выводов нужны разные размеры, плотности, ресурсы и много seed, а не только повтор одного набора.

## Воспроизводимые результаты и проверки

В `main part/results/` лежат реально выполненные серии **seed 42–46** с настройками по умолчанию: 48×40, 24 человека, 3 дрона, 4 робота, горизонт 360, популяция 24, 8 поколений. В JSON сохранены параметры, версия Python/платформы, время и результаты каждого seed. Полные значения в CSV/JSON; времена CPU зависят от ПК и нагрузки.

| Страница | Метод | Людей, среднее | Баллы, среднее | CPU одного плана, мс |
|---|---|---:|---:|---:|
| Разведка | Прирост покрытия | 24.0 | 99.689 | 0.054 |
| Разведка | NSGA-II | 24.0 | 99.661 | 12.15 |
| Разведка | Ближний сектор | 24.0 | 99.642 | 0.042 |
| Разведка | Полосовой обход | 24.0 | 99.185 | 0.055 |
| Эвакуация | Локальный поиск | 16.0 | 66.516 | 1.43 |
| Эвакуация | NSGA-II | 15.8 | 65.726 | 18.31 |
| Эвакуация | Ближайший человек | 15.6 | 64.919 | 0.027 |
| Эвакуация | Сначала срочные | 15.4 | 64.123 | 0.022 |

На этой небольшой серии NSGA-II уступает локальному поиску; жадное покрытие сильнее в разведке. Это стартовый результат для улучшения постановки, операторов и стратегии перепланирования, а не основание объявлять NSGA-II лучшим или бесполезным. Честные исходные методы нужны именно для обнаружения таких случаев.

Команды в распакованной папке:

```powershell
python -B -X utf8 -m unittest discover -s "main part/tests" -v
$env:PYTHONPATH = (Join-Path (Get-Location) 'main part')
python -B -X utf8 -m rescuebench.cli --mode both --count 5 --seed 42 --output results-new
Remove-Item Env:\PYTHONPATH
```

## Структура и границы

```text
main.py / main.cmd        запуск, локальное venv, браузер
requirements.txt         внешних зависимостей нет
venv/                    создаваемое на этом ПК окружение
main part/
  rescuebench/domain.py      генератор и наземные пути
  rescuebench/nsga2.py       универсальное ядро NSGA-II
  rescuebench/planning.py    планировщики и декодеры
  rescuebench/simulation.py  события, движение, метрики
  rescuebench/batch.py       серии и статистика
  rescuebench/server.py      HTTP API и локальная раздача UI
  rescuebench/cli.py         серия без браузера
  web/                      HTML / CSS / Canvas / JavaScript
  tests/                    unittest и QA.md
  results/                  измеренная стартовая серия
```

Это отдельный исследовательский стенд, а не финальная реализация среды/контроллера по ТЗ хакатона. Динамические разрушения, ошибки датчиков, столкновения, связь, ретрансляторы, риск, метасценарии и Unreal-физика сюда не включены. Перенос в 3D требует заменить источник наблюдений, пути и исполнитель движения, а затем заново проверить ограничения; одного добавления координаты z недостаточно. Ядро NSGA-II и экспериментальную методику можно использовать повторно.
