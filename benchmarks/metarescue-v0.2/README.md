# MetaRescue Benchmark Lab — интерактивный прототип (версия 0.2.0)

Локальное приложение на Python с браузерным интерфейсом. Обновление 0.2: масштабируемые карты/парк, читаемые графики, расширенные метрики и рейтинги. **Пять методов разведки**, **четыре метода эвакуации** (+ настоящий OR-Tools, если установлен) и **пять комбинированных конфигураций**, которые выполняют разведку и эвакуацию одновременно.

**Важно:** это исследовательский **2D-бенчмарк**, не законченная 3D-среда по нормативной спецификации «Метарой 1.0» и не окончательный метасценарный контроллер. API `/api/simulation` предназначен только для лабораторных прогонов.

## Быстрый старт (Windows)

1. Установите **Python 3.10+** с https://www.python.org/downloads/ . Во время установки Windows отметьте **Add Python to PATH**.
2. Распакуйте весь ZIP в обычную папку, например `C:\MetaRescue` (лучше не внутри защищённых каталогов).
3. **Дважды нажмите `main.bat`**. Либо `main.py`, если `.py` корректно ассоциированы с Python.
4. На первом запуске создастся локальная папка `venv/` с виртуальным окружением. Интернет для основного приложения не нужен. В браузере автоматически откроется `http://127.0.0.1:8765/` (при занятом порте приложение сообщит другой).
5. Держите окно терминала открытым, пока используете сайт. Закрыть: `Ctrl+C`.

## macOS / Linux

Откройте терминал в распакованной папке и выполните:

```bash
python3 main.py
```

На macOS также есть `main.command`. Если у него нет разрешения запуска: `chmod +x main.command`.

## Обязательные зависимости

Только Python 3.10+ и современный браузер (Chrome, Firefox, Edge, Safari). **Ничего устанавливать через pip для основной версии не требуется.** `requirements.txt` сохранён для стандартной структуры проекта.

### Опциональный сильный бенчмарк OR-Tools

Четыре алгоритма эвакуации работают без сторонних библиотек. Чтобы добавить пятый — **реальный CP-SAT решатель Google OR-Tools** — остановите сервер, затем запустите из папки проекта:

**Windows:**

```bat
venv\Scripts\python.exe -m pip install -r requirements-optional.txt
```

**macOS/Linux:**

```bash
venv/bin/python -m pip install -r requirements-optional.txt
```

После перезапуска приложения появится дополнительная панель `OR-Tools CP-SAT` на странице «Эвакуация». Если OR-Tools не установлен, мы не подменяем его результатами другого метода. Для его установки нужен интернет один раз.

## Страницы

- **01 · Разведка** — одновременно Random Search, Sweep, Greedy, Frontier-based, Scout NSGA-II. Карты одинаковы, но каждый алгоритм формирует собственные маршруты и находит людей в разные моменты времени. Важные метрики: обнаруженные люди, обследованные сектора, энергия, время построения плана.
- **02 · Эвакуация** — Nearest Robot, Greedy, Local Search, Rescue NSGA-II и опциональный OR-Tools CP-SAT. **Изолированный offline-бенчмарк:** для корректного сравнения маршрутизаторов все положения людей известны в начале.
- **03 · Общая миссия** — пять комбинаций поиска и эвакуации. Начало эвакуации происходит сразу после обнаружения людей, а не после всей разведки. На каждом существенном событии планировщик получает только уже обнаруженные цели.

## Управление

- Выбор **S1–S6** — отдельные сценарии: S1 открытая местность; S2 разрушенный город; S3 скрытые скопления пострадавших; S4 дефицит батарей; S5 неполная информация с детерминированными пропусками сенсора; S6 отказ наземного робота на 95-й модельной секунде (в полной миссии отменяет незавершённый рейс и вызывает переназначение).
- **▶ / ❚❚** — воспроизведение или пауза;
- **⏭** — один шаг на 5 модельных секунд;
- **↺** — перемотка в начало;
- ползунок — ручная перемотка времени;
- переключатель скорости: 1×, 4×, 12×, 30×, 60×;
- `seed`, **размер карты (25×25, 35×35, 45×45, 55×55, 65×65)**, **количество дронов (1–10)**, **эвакуаторов (1–12)** и **пострадавших (3–80)** — создают новую воспроизводимую сцену;
- **Скачать результаты JSON** — экспорт полных трасс, параметров NSGA-II и итоговых метрик.

## Что нового в версии 0.2

- **Графики больше не накладываются друг на друга.** Каждый алгоритм имеет собственную кривую количества найденных/спасённых людей, но все используют одинаковый масштаб по оси X (модельное время) и Y (число людей). Пунктирная линия показывает положение воспроизведения.
- **Настраивается реальная модель**, а не только подписи: карта, число дронов, эвакуаторов и пострадавших передаются серверу, учитываются планировщиками, маршрутами, ограничениями и визуализацией. Размер сектора — 5×5 клеток. Крупные карты имеют пропорционально более длинный горизонт миссии и больший запас энергии на каждого робота; дефицит энергии S4 сохраняет относительный характер.
- **Сводная таблица** теперь показывает место, баллы, количество спасённых, темп (человек/мин), среднюю продолжительность завершённого рейса (секунд/человек), потраченную энергию, время последней доставки, время окончания активности всех роботов/дронов (секунды) и вычислительное время планирования. Для разведки дополнительно отображаются найденные люди, число обследованных секторов и темп обнаружения.
- **Баллы 0–100** — прозрачный внутренний индекс для удобного сравнения в текущий момент, **не официальная оценка хакатона**. Результаты сортируются по индексу, победитель выделяется. Формулы:
  - Разведка: **65%** доля найденных + **25%** ранние обнаружения + **10%** эффективность энергозатрат.
  - Эвакуация: **70%** доля спасённых + **20%** ранние доставки + **10%** эффективность энергозатрат.
  - Общая миссия: **60%** доля спасённых + **15%** доля обнаруженных + **15%** ранние доставки + **10%** эффективность энергозатрат.
  - «Ранние» — сумма `(1 − момент_обнаружения_или_доставки / лимит_миссии)` по всем успевшим людям, поделённая на общее число людей. Энергетическая доля = `доля_результата × max(0, 1 − энергия_потрачена / (90% исходного суммарного запаса))`. При нулевых результатах чистое бездействие не получает баллы за экономию.
- **Время окончания работы** — время последней активности (полет/движение/доставка) в пределах лимита симуляции. Оно **не означает**, что все пострадавшие спасены или все сектора обследованы. Время последней успешной доставки показано отдельно.
- **Темп спасения** = `спасённых × 60 / время последней доставки` (чел./мин с момента старта). **Средний рейс** = среднее `(время доставки − время отправления на рейс)` только для завершённых рейсов. Доступно сразу под картами и в сводной таблице.

Для первого теста рекомендуем 25×25, 3 дрона, 4 эвакуатора, 16 пострадавших. На максимальных настройках генерация результатов может занимать заметно больше времени. Все числа и модели по-прежнему синтетические и нужны для сравнения алгоритмов, а не для оценки реальных роботов.

## Что реально реализовано

- Настоящий **NSGA-II**: недоминируемая сортировка, crowding distance, crowded tournament, элитистское сохранение, OX crossover и мутация перестановок и назначений.
- Два специализированных кодирования: назначения сектора→дрон и пострадавшего→эвакуатор с порядком обслуживания.
- Ground A* на проходимой сетке с весом рельефа; воздушные дроны по прямой (текущая упрощённая модель).
- Несколько роботов работают параллельно, энергетический резерв и лимит времени проверяются при оценке эвакуационных планов.
- Политики сравниваются **на одном seed, с одинаковым рельефом, позициями людей, энергией и временем миссии**.
- Истинные координаты людей скрыты от алгоритмов разведки. Начальный prior основан на открытой карте разрушений, и **не вычисляется по истинному размещению людей**.
- При обследовании сектора люди обнаруживаются детерминированно: сенсор идеален в S1–S4 и S6; в S5 каждый человек имеет воспроизводимый 17%-ный риск пропуска, одинаковый для всех методов.
- В общей миссии обнаружения `target_detected` вызывают перепланирование эвакуации; уже начатые рейсы не прерываются.
- Фронт Парето в аналитике — реальные результаты NSGA-II на текущем seed, не нарисованные примеры.
- **Время алгоритмов измеряется** `time.perf_counter()` и зависит от компьютера; у сравниваемых методов используются разные бюджеты, поэтому по одному графику нельзя утверждать превосходство при равном вычислительном бюджете.

## Оговорки исследовательской модели

1. Все параметры симуляции являются **синтетическими**. Это не физическая сертификация спасательных роботов. 1 клетка = 10 м, но модели скоростей, рельефа и батарей упрощены.
2. Дрон обследует сектор целиком из его центра; сенсор идеален, кроме S5, где есть ложные отрицания, заранее определённые seed. Ложных срабатываний пока нет.
3. Воздушные маршруты рассчитываются евклидовыми отрезками, без 3D-препятствий и ветра. S6 динамически моделирует отказ эвакуатора в полной миссии; остальные автономные страницы S6 не реализуют перепланирование под отказ.
4. Эвакуатор за один рейс доставляет **ровно одного** человека на общую базу; в текущей модели зарядка отсутствует.
5. Сравнение на одной случайной карте не является статистическим доказательством превосходства. Для исследования запускайте разные `seed`, экспортируйте результаты и вычисляйте распределения метрик.
6. Во время динамической миссии повторная оптимизация формирует расписание по известным целям, но фиксирует только следующие рейсы свободных эвакуаторов. Это **event-driven rolling horizon**, а не полное перепланирование движения на каждый кадр.
7. Для научно строгого сравнения потребуется одинаковый вычислительный бюджет для NSGA-II и других оптимизаторов, детерминированные seed алгоритмов и многократные повторы на случайных картах.
8. Протокол HTTP/JSON «Метарой 1.0» (`/v1/environment/*`, `/v1/controller/*`) и обязательные метасценарные операции **не реализованы полностью в данной версии**. Их следует сделать отдельным этапом после проверки планировщиков.

## Пакетный бенчмарк (CSV по нескольким картам)

Для сравнения на 30 независимых картах с разными seed:

```bash
python "main part/benchmark_batch.py" --seeds 30 --mode all --scenario urban --people 16 --output results_30.csv
```

Результаты записываются в CSV (кодировка UTF-8 с BOM, удобно для Excel). `--mode` может принимать значения `scout`, `rescue`, `mission` или `all`; `--scenario` — `open`, `urban`, `clusters`, `scarce`, `uncertain`, `dynamic`. Программа выведет усреднённые результаты по алгоритмам. Для быстрых начальных проверок используйте `--seeds 3`.
