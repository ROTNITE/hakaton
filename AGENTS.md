## Правила работы

- Приоритетное исключение от 13.11.2026: на ближайшей безопасной границе первым
  взять P1 / ADD-09 из `docs/additional-tasks.md` (самостоятельный выбор и
  применение материала лекций по теории игр и/или оптимизации), затем вернуться
  к P0. Подробный порядок — `docs/quarter-v052-priorities.md`.

- Если нужной 3D-модели/ассета нет в библиотеке проекта, самостоятельно проводить
  подробный поиск подходящих материалов в интернете и подключать выбранные
  модели в игру. Проверять тематику, лицензию, совместимость с UE5 и стоимость
  рендера; сохранять оригиналы и происхождение. Подробный порядок — ADD-08 в
  `docs/additional-tasks.md`. Это разрешение на поиск, загрузку и интеграцию
  подходящих доступных ассетов в рамках текущего плана, без покупки от имени
  пользователя и без остановки текущих сборок/прогонов.

- **Отложенные дополнительные задания пользователя:** `docs/additional-tasks.md`.
  Перечитывать при следующем чтении инструкций, между этапами, после завершения
  текущей сборки/прогона и перед окончательной приёмкой. Не прерывать текущую
  операцию и не нарушать freeze ради этих заданий. Новые пункты самостоятельно
  включать в подходящие оставшиеся этапы `docs/quarter-v052-execution.md` и
  `docs/quarter-v052-acceptance.json`, отмечая в очереди статус и свидетельства.
  Это дополнение к утверждённому плану, а не отмена текущего поручения; простое
  прочтение или перенос в план не означает выполнение. Существенные открытые
  решения соблюдать по границам, указанным в файле.
  Пункт ADD-06 отдельно требует проверить использование уже скачанных деревьев
  из `blender/vegetation/` и подключить подходящие недостающие модели в игру.
  Пункт ADD-07 требует постоянного подробного учёта API-вызовов, токенов,
  стоимости и ошибок с сохранением журнала и сводок; общий LIVE-лимит не увеличивать.

- До изменений изучить структуру, относящиеся к задаче документы, код, аналогичные реализации и доступные команды проверки. Следовать существующей архитектуре и стилю.
- Для нетривиальной задачи сначала составить короткий план. Существенную неоднозначность в архитектуре, безопасности, совместимости или необратимых действиях уточнить одним вопросом; остальные допущения явно обозначить.
- Делать минимально достаточные изменения, устранять причину проблемы, сохранять чужие правки и внешние интерфейсы. Не проводить несвязанный рефакторинг; зависимости менять только при необходимости с объяснением.
- Без явной задачи не удалять старые материалы и не заменять корневую архитектуру. Оригинальные пользовательские архивы и их хэши сохранять; изменения импортированных реализаций и импортов не делать молча. Старый Evolution World удалён пользователем — не восстанавливать.
- Генерируемые файлы не править вручную. Не раскрывать секреты и не ослаблять защиту ради удобства реализации.
- Самостоятельные 2D-бенчмарки, физический 3D-стенд и нормативный контракт среды/контроллера держать раздельно. Не смешивать результаты разных моделей и не объявлять стенд готовой конкурсной системой.
- Для изменённого поведения добавлять или обновлять применимые тесты; ошибку по возможности воспроизводить до исправления. Сначала запускать узкие проверки, затем применимые общие команды ниже; перед завершением просматривать итоговый diff.
- Не выдавать предположения, старые отчёты или неисполненные команды за новую проверку. В итоге указывать изменения и файлы, выполненные команды и результаты, непроверенное, ограничения и риски; при блокировке — точную ошибку и следующий шаг.

## Текущие решения и границы

- Дроны ищут скрытых людей; эвакуаторы одновременно доставляют найденных в пункт помощи. Два NSGA-II отвечают за разведку и эвакуацию. Среда владеет истинным состоянием, контроллер — только полученными наблюдениями. Преимущество NSGA-II должно проверяться, а не предполагаться.
- Историческая динамическая 2D-база v0.3 в `benchmarks/metarescue-v0.3/`: 16 файлов импортированы без правок. Python 3.10+, стандартная библиотека, A*, один человек за рейс, без зарядки, общий горизонт. v0.2 (19 файлов) сохранена отдельно. Активный перенос использует v0.5.2 выше.
- Три страницы: разведка, offline-эвакуация и online-миссия. Пять связок: greedy+greedy, frontier+local, nsga2+greedy, greedy+nsga2, nsga2+nsga2.
- В v0.3 восемь вероятностей задаются на **30 модельных секунд**, используется общая лента событий, есть динамика и поздние цели. Аудит воспроизвёл перерасход энергии сервисного действия и округление старта пути; оригинал не исправлялся. OR-Tools, JSON-кнопка и автоматическое venv из v0.2 отсутствуют. Ретрансляторов нет.
- `benchmark/` — отдельный ранний черновик с другими энергией, дедлайнами и оценкой. Он не подменяет пользовательские v0.2/v0.3.
- Принят контракт этапа 1: редакция документа 1.1, Core Protocol 1.0. `environment/`, `controller/`, `web/` — основной каркас; лабораторный API не заменяет нормативное взаимодействие независимых среды и контроллера.

```powershell

python -B -X utf8 -m unittest discover -s "benchmarks/MetaRescue_Benchmark_v0_5_2/main part/tests" -v
python -B -X utf8 -m unittest discover -s "benchmarks/metarescue-v0.3/main part/tests" -v
python -B -X utf8 -m unittest discover -s tests -v
python -B -X utf8 tools/run_mission.py --layout "D:/MetaRescue-output/worlds/core-static-rescue-01.private.json" --policy nsga2_nsga2 --ai-mode MOCK
git diff --check
```

При изменениях соответствующих исторической версии или черновика:

```powershell
python -B -X utf8 -m unittest discover -s "benchmarks/metarescue-v0.2/main part/tests" -v
python -B -X utf8 -m unittest discover -s "benchmark/main part/tests" -v
```

## Физический 3D-стенд

Проект: `unreal/MetaRescue/MetaRescue.uproject`, C++, Unreal Engine 5.8 (проверен 5.8.4). Для сборки нужны Visual Studio C++ toolchain и Windows SDK.

```powershell
python -B -X utf8 unreal/launch.py --quarter --editor
python -B -X utf8 unreal/launch.py --quarter --build
python -B -X utf8 unreal/launch.py --quarter --smoke --mechanics-probe --smoke-seconds 270
python -B -X utf8 unreal/tools/check_quarter.py
python -B -X utf8 unreal/tools/check_environment_probes.py
```

Текущая карта — `/Game/Maps/RescueQuarter`, отдельный сценарий `Content/Scenario/quarter.json`. Проверены 26 исходных комплектов; производные Blender/FBX/PBR находятся в `blender/prepared/v2/`, оригиналы не менять. Сборка включает 341 отдельную деталь, механизмы агентов, исправленное стекло, целые/повреждённые здания и инфраструктуру. Генераторы, импорт и проверки — `unreal/tools/`; обзор по каждому исходнику — `docs/3d-asset-library-review.md`.

Семь основных агентов движутся физически; 23 Chaos-обломка, погрузка с рампой и грузом, очередь наблюдений при отказе связи, поздняя цель, грязь/глубина воды/пожар имеют последствия. Два дополнительных механических пробника включаются только флагом выше. Полные результаты текущего прогона, границы и пути свидетельств — `docs/3d-world-status.md` и `unreal/QA.md`. Этот абзац относится к legacy-демонстрации. Новый CoreHTTP-срез, отдельный NSGA-II x2 контроллер и Global/Local проходят собственные проверки; точный объём и ограничения — в execution/handoff. Полная конкурсная матрица, UI, серии и пакет ещё не завершены.

`unreal/launch.py --smoke` без `--quarter` запускает прежнюю `/Game/Maps/RescueDistrict` для регрессии. Её umap и исходный сценарий сохранены. Не запускать два native smoke одновременно: они пишут в один Saved. До нового прогона архивировать свежие кадры/телеметрию отдельно.

В UI новой карты проверены пресеты 1/2/4/6/8, выбор стрелкой, R, колесо, Space и F9; у ранней сцены ранее проверены Tab/W. RMB, отдельные A/S/D и раннее F отдельно не подтверждены. Skeletal Walking/Running/дыхание подготовлены и проверены по костям, но пострадавшие в миссии пока статические. Повторную генерацию производных выполнять скриптами; обычный запуск ничего не пересоздаёт.
