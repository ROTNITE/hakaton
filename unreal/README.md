# MetaRescue — физический 3D-стенд Unreal

## Нативная среда Core и отдельный контроллер

Из корня проекта после установки `requirements.txt` и закрытия редактора

```powershell
python -B -X utf8 tools/run_mission.py --build --policy nsga2_nsga2 --ai-mode MOCK --visible
python -B -X utf8 unreal/launch.py --automation MetaRescue.Core
```

Эти команды выполняются последовательно. Runner запускает генератор района,
Unreal и отдельный Python-контроллер. В `D:/MetaRescue-output/missions/` остаются
конфигурация, статусы процессов и журналы. Сведения о текущей приёмке в
`../docs/quarter-v052-handoff.md`. Разделы ниже описывают локальный стенд v3.

## Текущая карта: RescueQuarter и библиотека v2

Для новой сцены с доработанными пользовательскими моделями:

```powershell
python -B -X utf8 unreal/launch.py --quarter --editor
```

Открывается `/Game/Maps/RescueQuarter`; нажмите Play. `RescueDistrict` ниже — сохранённый ранний стенд. Новая карта использует отдельный сценарий `Content/Scenario/quarter.json` и локальную демонстрационную политику. Runtime NSGA-II и нормативный внешний контроллер к ней пока не подключены.

Квартал собран из проверенной библиотеки `blender/prepared/v2/`: целые и частично разрушенные модульные дома, руины, медпункт, доки, машина, инженерные сети, сенсоры, связь, завалы и водный участок. Обзор всех 26 источников и исправлений — `../docs/3d-asset-library-review.md`; результаты текущей версии — `../docs/3d-world-status.md`.

Управление новой картой:

- `1–8` — база, обзор квартала, обрушение, вода, тоннель, пожар, улица, близкий вид ровера.
- `I` — инспектор; стрелки влево/вправо — агент; `R` — слежение за выбранным агентом.
- Колесо — масштаб; RMB — поворот; WASD — перемещение, отключающее слежение.
- `Space` — пауза/продолжение; `Tab` — общий/начальный вид; `F` — раннее обрушение; `F9` — PNG в `Saved/Screenshots/`.

Анимации работают по состоянию: роторы запускаются/останавливаются, гимбал осматривает местность, катки и ленты следуют скорости и повороту, рампа/выдвижение/лебёдка участвуют в загрузке. Машина паркуется и открывает задние двери; у неё вращаются колёса и мигают маяки. Сенсорные головки сканируют, оборудование базы имеет ограниченную служебную анимацию. Скелетные Walking/Running/дыхание подготовлены отдельно; лежащий пострадавший в сцене использует статическую позу.

Обрушение — реальные Chaos-тела. Пыль сокращает дальность сенсора, сообщения сохраняются при потере ретранслятора, поздний пострадавший появляется после изменения доступности. Грязь снижает скорость; мелкая вода замедляет, глубокая вода и опасная зона огня останавливают незащищённый ровер. Роверы используют шесть лучевых опор и ограниченную тягу; перевозимый груз меняет массу/центр масс. Подробные упрощения и численные результаты проверок перечислены в статусе.

Сборка и проверка нового квартала:

```powershell
python -B -X utf8 unreal/launch.py --quarter --build
python -B -X utf8 unreal/launch.py --quarter --smoke --mechanics-probe
python -B -X utf8 unreal/tools/check_quarter.py
python -B -X utf8 unreal/tools/check_environment_probes.py
```

Длительный прогон по умолчанию — 240 модельных секунд, в нём семь основных агентов. `--mechanics-probe` добавляет две отдельные проверочные машины у воды/грязи; они не участвуют в диспетчере спасения. `--visible` показывает игровое окно, `--smoke-seconds` задаёт длительность. Короткий прогон не доказывает завершение доставки.

Импорт подготовленных файлов выполняется установленным UE, при закрытой игровой сцене:

```powershell
$rescueEditor = 'C:/Program Files/Epic Games/UE_5.8/Engine/Binaries/Win64/UnrealEditor-Cmd.exe'
$rescueProject = (Resolve-Path 'unreal/MetaRescue/MetaRescue.uproject').Path
$rescueScript = (Resolve-Path 'unreal/tools/import_asset_library.py').Path
& $rescueEditor $rescueProject -run=pythonscript "-script=$rescueScript" -unattended -NoSound -stdout -FullStdOutLogOutput
```

Для отдельной сборки добавьте, например, `'-MRLibraryAssets=Van,Drone'`. Затем тем же способом выполните `import_mannequin_rig.py` для skeletal-файлов и `build_library_scene.py` для эффектов и карты. Скрипты чтения готовых файлов — `verify_asset_library.py` и `verify_quarter_map.py`. Повторная генерация заменяет производные ассеты; обычный запуск `--editor` их не перестраивает.

## Сохранённый ранний стенд RescueDistrict

Далее описаны исходный импорт v0.3 и его отдельные проверки от 9 ноября. Их численные результаты относятся к старой карте.

Отдельный C++-проект Unreal Engine **5.8**. После получения нового архива карта экспортируется из пользовательского **MetaRescue Benchmark v0.3**; v0.2 также поддерживается экспортёром для исторического сравнения. Не заменяет ни 2D-бенчмарк, ни нормативный контроллер.

## Открыть на этом компьютере

Из корня репозитория:

```powershell
python -B -X utf8 unreal/launch.py --editor
```

Либо открыть `unreal/MetaRescue/MetaRescue.uproject`. Сцена: **Content → Maps → RescueDistrict**. Нажать Play. `unreal/launch.cmd` вызывает тот же Python-лаунчер. Путь установленного движка по умолчанию: `C:\Program Files\Epic Games\UE_5.8`; другой путь передаётся `--engine "D:\Epic\UE_5.8"` или переменной `MR_UNREAL_ENGINE`.

Если C++-модуль ещё не собран или ассеты не созданы:

```powershell
python -B -X utf8 unreal/launch.py --build --setup --editor
```

Понадобятся установленный Unreal 5.8, Visual Studio с C++ toolchain/Windows SDK и Python 3.10+. В проекте используются встроенные Engine, PhysicsCore, ProceduralMeshComponent и редакторский Python. Сторонних пакетов Python, внешних моделей и лицензируемых наборов ассетов нет. Сам движок/SDK в репозиторий не копируются.

`--setup` сохраняет существующую подготовленную карту. `--rebuild-scene` явно пересоздаёт геометрию, управляемую кодом, и повторно применяет материалы/свет; ручные изменения этих генерируемых частей следует делать в исходном генераторе или в отдельных актёрах, а не рассчитывать на сохранение при регенерации. Обычный запуск сцены ничего не пересоздаёт.

## Управление

- Правая кнопка мыши и движение — поворот камеры.
- Колесо — приближение/отдаление.
- WASD — перемещение фокуса по площадке.
- Tab — весь участок / начальный вид.
- F — досрочно отпустить плиты демонстрационного обрушения.
- Space — пауза/продолжение физики.
- F9 — сохранить реальный скриншот в `MetaRescue/Saved/Screenshots/`.

В редакторском Play сначала кликнуть в игровую область; Shift+F1 возвращает курсор редактору. Эти стандартные элементы редактора не являются частью алгоритма.

## Что делает сцена

Статическая карта 25×25 из v0.3 превращается в участок **250×250 м**: 10 м/клетку, 1000 Unreal-сантиметров/клетку. Дороги, повреждённые здания с открытыми перекрытиями, отдельные обломки, водные участки, следы трудной поверхности, пункт помощи, оборудование и служебная машина создаются процедурно. Водные клетки — поверхность и ограничение проезда, не гидродинамика. Материалы используют мировые координаты и шум для неоднородности поверхности. Сохранённая карта содержит геометрию, её можно осматривать в редакторе.

Три дрона и четыре эвакуатора создаются при Play. Корпуса — физические тела Chaos. Дроны удерживают высоту и движутся к точкам, экспортированным из Scout NSGA-II v0.3. Наземные роботы управляются силами и поворотным моментом, а не анимацией заранее заданной позиции. Физические коллизии могут остановить/изменить их движение.

Сенсор демонстрации проверяет расстояние и прямую видимость до человека. Люди существуют в истинном состоянии среды; назначение возможно только после обнаружения. Простой демонстрационный диспетчер направляет свободных эвакуаторов к найденным людям. Подъём, перевозка и передача отражаются в журнале; счётчик доставки увеличивается после возвращения в пункт и окончания передачи.

**Runtime Rescue NSGA-II и метасценарный контроллер ещё не подключены.** Это явно обозначено в HUD. Здесь не измеряется качество пяти связок v0.3: для такого эксперимента нужно заменить демодиспетчер, согласовать наблюдения/время и повторно провести сравнение. Разведка в 3D также использует иной физический сенсор, поэтому результаты нельзя напрямую приравнивать к секторной модели 2D-бенчмарка.

Всего подготовлены 23 динамических обломка. Пять плит сначала удерживаются, на 18-й секунде или по F освобождаются и падают с гравитацией, вращением и столкновениями. Это изменение физических тел, а не нарисованная смена их положения. Полноценная модель разрушения материала/устойчивости здания этим не заявляется.

Вероятностные пожары, вода, дым и поздние цели полученной 2D-версии v0.3 **ещё не перенесены в Unreal**. Их требования и фактическое выполнение в 2D разобраны в `docs/benchmark-v0.3-spec.md` и `docs/benchmark-v0.3-review.md`.

```text
unreal/

  tools/export_scenario.py    экспорт из пользовательского v0.3 (опционально v0.2)
  tools/build_scene.py        генерация uasset/umap через API редактора
  tools/check_smoke.py        проверка фактических физических исходов
  tools/verify_scene.py       чтение карты и проверка ссылок в распакованном проекте
  MetaRescue/
    MetaRescue.uproject
    Config/                   карта, рендеринг, подшаги физики
    Source/MetaRescue/         мир, агент, камера, HUD, GameMode
    Content/Scenario/          исходное состояние среды и provenance
    Content/Materials/         созданные редактором материалы
    Content/Maps/              сохранённая RescueDistrict
    Saved/                    локальные логи/снимки/телеметрия; не исходники
```

`Content/Scenario/scenario.json` содержит **истину среды**, включая скрытых людей и исходные пути. Его нельзя передавать внешнему контроллеру как Observation. При интеграции наружу публикуется только реально наблюдаемое состояние по принятому контракту.

Локальный исполнитель принимает маршруты в `AMRAgent::SetWaypoints`.
В генерируемой среде Core HTTP/JSON связывает этот исполнитель с независимым
Python-контроллером. Редакторский Python используется для подготовки контента.

## Проверки

```powershell
python -B -X utf8 unreal/launch.py --build
python -B -X utf8 unreal/launch.py --smoke
```

Smoke запускает настоящий движок без видимого окна на **90 модельных секунд** по умолчанию (`--smoke-seconds 30..300`). Читает созданную движком свежую телеметрию, проверяет движение наземных/воздушных тел, контакты, падение плит, сохранность поверхности, сенсорные обнаружения и реальные PNG; для 90+ с — минимум одну завершённую доставку. Это не сравнение производительности NSGA-II и не фикстурная симуляция.

Фактически выполнено на UE **5.8.4**, RTX 3080, Windows: сборка и генерация успешны; прогон 90.005 с, 16 обнаружений, **1 завершённая физическая доставка**, 23 физических обломка и 7 агентов. Плиты действительно изменили высоту после освобождения. Счётчик CONTACTS — уведомления о контактах, включая повторные, а не число уникальных аварий.

Результат: `MetaRescue/Saved/Telemetry/latest.json`, `events.jsonl`, `Screenshots/scene-start.png`, `Screenshots/physics-smoke.png`, `Automation/*.log`. Доказательства проверенной версии копируются в `artifacts/unreal/`. Подробности — `unreal/QA.md`.

## Ограничения и следующий шаг

Это первая физическая площадка для развития проекта. Здесь нет полноценной модели гусеничного привода/подвески, связи и ретрансляторов, тушения/расчистки, разрушения Geometry Collection, нормативных метаопераций и гарантии битовой воспроизводимости Chaos между ПК. Наземные пути импортированы из статического снимка v0.3; реакция планировщика на физические обломки требует адаптера. В демонстрационном прогоне часть роботов упиралась в реальные препятствия — он не означает, что вся операция завершена. Условные батареи/скорости не являются характеристиками сертифицированного робота.

В обычном видимом игровом окне проверены Tab, колесо, перемещение W, Space (пауза/продолжение) и F9 с реальным файлом кадра. Поворот RMB, отдельные A/S/D и досрочное обрушение по F не проверены UI-действием. Смена ракурса на паузе отображается после продолжения. Первоначальные ошибки захвата Windows устранены повторным запуском с обновлённым инструментом; результаты UI-проверки и её границы — в `QA.md`. Физика проверена по свежим данным движка. Сборка прошла с предупреждением о MSVC 14.51 (предпочтительный у установленного UE — 14.50); это не тест на всех версиях компилятора.

Отдельно карта успешно загружена из распакованного проектного ZIP: один нативный MRWorld, 1343 компонента StaticMesh со всеми ссылками на модели и материалы. Проверено в том же установленном UE 5.8.4, не на другом ПК. Проверка: `tools/verify_scene.py` через редакторский Python commandlet; отчёт `artifacts/unreal/package-scene-check.json`.

Следующий этап: общий слой событий v0.3 → публичные наблюдения и подтверждённые команды → внешний Python-планировщик → проверка пяти связок и метауровня в физической среде. Визуальная цель и первоначальный imagegen-prompt сохранены в `docs/3d-visual-direction.md`; изображение-концепт не является скриншотом этой сцены.
